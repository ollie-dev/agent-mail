# Agent Mail

## Stack

- Language: Rust, one binary crate (see `docs/adr/0001-rust-not-bun.md`)
- Targets: macOS (`aarch64-apple-darwin`, `x86_64-apple-darwin`) and Windows x64 (`x86_64-pc-windows-msvc`); Windows APIs come from `windows-sys`. `.gitattributes` (`* text=auto eol=lf`) keeps LF line endings on Windows checkouts, which the source and Markdown tests rely on; CI runs `cargo test --locked` on macOS and Windows
- Test: `cargo test`
- Lint: `cargo clippy -- -D warnings` and `cargo fmt --check`
- Source and test layout: one Cargo package `agent-mail` at the repo root (`Cargo.toml`, committed `Cargo.lock`); `src/main.rs` is the thin binary entry point that parses arguments and hands off; `src/lib.rs` is the library target holding the CLI definition, the core and the adapters, so tests can drive them in-process; modules under `src/` split the core (`core.rs`, including opening the presented tokens, target-Account resolution, Mandate selection and `whoami`), the Mandate model (`mandate.rs`), sealing (`seal.rs`), the Mandate store port with the macOS Keychain store, the Windows `CredentialManagerStore` with its `credential_layout` (target names, splitting values over the 2,560-byte blob limit) and the `GuardedStore` wrapper that runs the hardened-runtime self-check before every store call (`store.rs`), the hardened-runtime self-check with `csops` and the `hardened_runtime_ok` decision, active only in macOS release builds (`src/selfcheck.rs`), the Terminal port, writing messages and the Agent Token to `/dev/tty`, or `CONOUT$` on Windows (`terminal.rs`), the `mandate create` guided flow (`create.rs`), the TOML Mandate file written by the export offer and read by `mandate create --from` (`export.rs`), the IMAP connector (`imap.rs`), the proxy setting read from `HTTPS_PROXY`/`ALL_PROXY` with the hand-written HTTP CONNECT and SOCKS5 handshakes (`proxy.rs`), modified UTF-7 decoding and encoding (`utf7.rs`), message search with its criteria, result types and message reference (`search.rs`, including the `--gmail` query sent as `X-GM-RAW`), reading one message with its result types, MIME-to-text conversion and truncation (`read.rs`), setting and clearing the `\Seen` and `\Flagged` flags with the flag name parsing and result type (`flag.rs`), moving one message between mailboxes with its result type and `--text` line (`move_message.rs`), creating drafts with the result type and its `--text` line, recipient and subject validation, building the RFC 5322 message and the reply helpers (`draft.rs`), the append-only audit log with its platform path rule, Local AppData on Windows, and the Broker's log under `%ProgramData%` with each entry's `sid`, and reading it back for `agent-mail audit` (`audit.rs`), the Windows Broker of ADR-0004 (`src/broker.rs`, on every OS: the `Request`/`Reply` protocol, the length-prefixed framing capped at 1 MiB, the version handshake, the `Caller`, request handling over any `Read + Write` transport, `SerializedStore` and the SDDL builders; `src/broker/windows.rs`, Windows only: the service control manager entry point behind the hidden `agent-mail broker` subcommand, the named-pipe server, impersonation, the access lists, the audit folder checks, and for the clients the `PipeConnector` that checks the pipe is owned (the `O:` of `pipe_sddl`) and served by `NT SERVICE\agent-mail` and the `TokenElevation` check), the Broker client of ADR-0004 (`src/client.rs`, on every OS: the `Connector` port, the session with its `hello`, `run`, `create` and `audit` requests, and rendering replies exactly as the CLI and the MCP server do in-process; on Windows `src/main.rs` routes every command through it) and the MCP server over stdio with its JSON-RPC loop, tool definitions, argument checks and result rendering (`src/mcp.rs`); `tests/` holds integration tests, one file per area (`tests/cli.rs`, `tests/project.rs`, `tests/list.rs`, `tests/sealing.rs`, `tests/create.rs`, `tests/export.rs` (the export offer and `mandate create --from`), `tests/mandates.rs` (`mandate list` and `mandate delete`), `tests/audit.rs` (the audit log and `agent-mail audit`), `tests/search.rs` (`search`), `tests/read.rs` (`read`), `tests/flag.rs` (`flag`), `tests/move_message.rs` (`move`), `tests/draft.rs` (`draft`), `tests/proxy.rs` (connecting through `HTTPS_PROXY`/`ALL_PROXY`, `proxy_refused`, `invalid_proxy` and built-in roots in proxy mode, against the in-process CONNECT and SOCKS5 proxies in `tests/support/proxy.rs`), `tests/mcp.rs` (the MCP server: tools, arguments, results and errors compared with the CLI, the protocol and the binary's `mcp` subcommand), `tests/client.rs` (the Broker clients: CLI, MCP and `mandate create` results compared in-process and through the fake Broker in `tests/support/broker.rs` on every OS, `broker_unavailable`, `broker_version_mismatch`, the elevation check, plus the Windows binary, pipe and server-identity tests), `tests/broker.rs` (the Broker's request handling through the in-memory fake transport in `tests/support/broker.rs` on every OS, plus the Windows pipe, access-list, audit-folder and stop tests and the opt-in, ignored-by-default service test run elevated with `cargo test --test broker -- --ignored`), `tests/tokens.rs` (several tokens in `AGENT_MAIL_TOKEN`, `--account`, Mandate selection, `ambiguous_mandate`, the invalid-token warning and `whoami`), `tests/selfcheck.rs` (the in-process `GuardedStore` tests, plus opt-in, ignored-by-default release-binary tests run on macOS with `cargo test --test selfcheck -- --ignored`), `tests/plugin.rs` (the Claude Code plugin manifests, the skill, the README setup sections and the placeholder-only scan of the plugin and README), `tests/release.rs` (the installers against a `file://` download directory, `install.sh` on macOS and `install.ps1` on Windows, and checks of the workflows, release notes, README and this file), `tests/credential_layout.rs` (the Credential Manager record layout, on every OS), the opt-in, ignored-by-default `tests/keychain.rs`, run with `cargo test -- --ignored keychain` on macOS, the opt-in, ignored-by-default `tests/credential_manager.rs`, run with `cargo test --test credential_manager -- --ignored` on Windows, and the opt-in, ignored-by-default live Gmail test `tests/gmail_live.rs`, run with `cargo test --test gmail_live -- --ignored` after exporting `AGENT_MAIL_LIVE_GMAIL_ADDRESS` and `AGENT_MAIL_LIVE_GMAIL_APP_PASSWORD` for a dedicated test account), with shared helpers and the in-process fake IMAP server in `tests/support/`
- Release files: the POSIX `sh` installer `install.sh` and the PowerShell installer `install.ps1` (Windows PowerShell 5.1 and PowerShell 7) at the repo root (both also uploaded as release assets); `scripts/` holds `sign-macos.sh` (ad-hoc signing with the hardened runtime, `--check-only` to verify) and `verify-release.sh <tag>` (checks a published release, including the Windows zip); `.github/workflows/release.yml` tests on macOS and Windows, builds the Windows zip in the read-only `build-windows` job, builds, signs, attests and publishes on a `v*` tag push and runs the `verify` job; `.github/workflows/ci.yml` runs the tests on macOS and Windows for pushes to `main` and pull requests; `.github/release-notes.md` is every release's body. `[profile.release]` pins `debug-assertions = false`, since debug builds skip the self-check
- Claude Code plugin: `.claude-plugin/marketplace.json` at the repo root is the marketplace `agent-mail` whose one plugin has `source` `./plugin`; `plugin/` holds `.claude-plugin/plugin.json` (the manifest), `.mcp.json` (the `agent-mail mcp` server, no token, only a `${AGENT_MAIL_TOKEN:-}` reference) and `plugin/skills/agent-mail/SKILL.md` (the Agent-facing skill). The plugin carries no binary and nothing executable
- Test-only code (the in-memory store, the scripted terminal, the trust-only-these-roots TLS hook, the connect override, the audit log redirect, `AuditLog::broker_at`, the Broker's pipe name override `serve_on` with `create_test_pipe` and `create_test_pipe_for`, the client's pipe override `AGENT_MAIL_TEST_PIPE` with `PipeConnector::new` and the fixed elevation status `Context::with_elevation`, and `GuardedStore::with_status` with its fixed code-signing status; test contexts write their audit log to a fresh temporary file, never the user's data directory) sits behind `cfg(any(test, feature = "test-support"))`; the `test-support` feature is never in `default` and is switched on for integration tests by the package's dev-dependency on itself

## Conventions

- Credentials never appear in logs, CLI output, agent-visible responses, test fixtures, or commits.
- Help text and error messages are short and say each thing once; split them into paragraphs or lines of at most about 300 characters.

## Software factory

Features are built by `/factory` (`.claude/skills/factory/SKILL.md`). State and job records live in `factory/`; each job is built on branch `factory/<job-id>` in the worktree `.worktrees/<job-id>/`. Dashboard: `cd factory && python3 -m http.server`, then open http://localhost:8000/dashboard.html.
