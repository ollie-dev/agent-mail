# The binary installs itself; the install scripts hand off to it

`agent-mail setup` first installs the running binary when it is not running from the install location: on macOS it copies itself to `~/.local/bin`, on Windows one elevated child copies it to `%ProgramFiles%\agent-mail`, registers and starts the Broker and puts the folder on the machine Path, as `install.ps1` does (ADR-0004). It then adds a Mandate and connects it to the human's Agent Apps. `install.sh` and `install.ps1` stay the verified download path: they check the release checksum, install, and end by handing off to `agent-mail setup`. We rejected keeping installation in the scripts only, because a first-time user then needs a script, a separate `mandate create` and hand-edited Agent App config files, and nothing checks the whole chain. The cost is that install logic exists twice (the scripts and the binary) and must stay in step, and that a binary downloaded in a browser, rather than by `curl | sh` or `irm | iex`, carries the quarantine flag or Mark of the Web, so Gatekeeper or SmartScreen warn before it can install itself. The one-liners stay the main path for that reason; paid signing (Developer ID and notarization, Authenticode) is a separate later decision, and would change what the Keychain binds a Mandate to (signing identity instead of code hash).
