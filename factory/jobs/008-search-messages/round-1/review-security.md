## Findings
- [nit] src/search.rs:35: `SearchText` refuses CR, LF and NUL, which is all IMAP quoted strings need. Other C0 controls (ESC, TAB, DEL) still go to the server inside the quotes. That is legal, but refusing every byte below 0x20 except TAB, plus 0x7F, would cost nothing and would keep agent-supplied control bytes out of the audit log `mailbox` field and out of error messages. Those are already JSON-escaped or passed through `escape_controls`, so this is defence in depth only.
- [nit] src/core.rs:333: the `denied` and `mailbox_not_found` messages repeat the Agent's mailbox string as given. That is safe: JSON output escapes it, and `--text` output passes it through `escape_controls`. Still, putting the name in quotes or backticks would show the Agent the exact boundaries of a name with spaces in it.

The core can only receive validated values, because the `SearchText`, `Date` and `Limit` fields are private and can only be built through their checking constructors, so an MCP adapter cannot get past the checks either.
