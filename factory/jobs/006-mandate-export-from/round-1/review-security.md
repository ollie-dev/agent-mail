## Findings
- [nit] src/create.rs:429 (hidden prompt in `add_account`): with `--from`, the server the Credential is sent to comes from an untrusted file. An Agent that can write files could plant one with `host = "imap.attacker.test"` and a real login. A human who accepts the defaults would then type the real password, and the live check would send it to that host. The host is already shown in the "Keep Account …?" question and the host prompt's default, so this is not blocking. Suggested fix: name the host in the Credential prompt (e.g. "Credential (password) for {login} on {host}:{port}:"), at least when the Account came from a file. If a Gmail-looking login is paired with a host other than `imap.gmail.com`, consider an extra confirm.
- [nit] src/export.rs:816 (`unknown_key`): the problem message echoes the key name (escaped). A quoted TOML key can hold any text, so a line like `"hunter2" = 1` puts the secret in stderr. This is unlikely in practice, and AC6 (b) requires naming `password`. Suggested fix: echo only keys that look like bare identifiers (`[A-Za-z0-9_-]`, short); for any other key, say "an unknown key at line N".
- [nit] src/export.rs:706 (`MandateFile::load`): `File::open` runs before the `is_file()` check, so passing `--from` a FIFO blocks the run. The path comes from the human, so this is not a security issue. Suggested fix: check `std::fs::metadata(path)?.is_file()` before opening, or open with `O_NONBLOCK`.
