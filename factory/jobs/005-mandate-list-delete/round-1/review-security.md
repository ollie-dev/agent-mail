## Findings
- [blocking] src/core.rs:418-438 (`mandate_delete`): delete removes only the *first* record whose unauthenticated clear listing carries the ID, in whatever order the store enumerates. Any process of the user can add a generic-password item under service `agent-mail` with no prompt. That includes an Agent, which ADR-0003 and the spec notes treat as able to run these commands. An Agent can plant a decoy record whose forged listing copies the ID (and name) of its own Mandate. When the human runs `mandate delete <id>`, Keychain order may pick the decoy. The command then prints `Deleted Mandate "..."` and exits 0, but the real record stays in place and the Agent's token keeps working. Revocation is the one guarantee `mandate delete` exists for, and the spec's notes only accept forged listings that "never widen what a token unlocks". Defeating revocation while reporting success is a different matter, and it is not the accidental-collision case that is out of scope. Expected fix: delete *every* record whose listing has that ID, not the first one, and report success only if at least one was removed. Alternatively, refuse with an ambiguity error that tells the human how many records share the ID. Add a test that stores A plus a decoy record whose listing has ID `aaaa1111`, runs `mandate delete aaaa1111`, and asserts that A's token then gets `invalid_token`.
- [nit] src/store.rs:117-125 (`accounts`): when the item account is not valid base64url, the key falls back to the raw account bytes. `delete(key)` then re-encodes it, so it would target a different account. This is harmless today, because such items never have a readable listing and so are never chosen for delete. Skipping (and counting) items whose account does not decode would be cleaner than the fallback.
- [nit] src/lib.rs:177-205 / src/terminal.rs:37: `escape_controls` escapes only `char::is_control` (Cc). Unicode format characters such as U+202E (RTL override) or U+200B in a forged name, host or mailbox pass through, so `--text mandate list` could be visually spoofed. The code is pre-existing, but this feature is the first to show untrusted store data to the human. Consider escaping Cf/bidi characters too.
